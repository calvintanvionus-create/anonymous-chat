# 畫面設計

> 這份文件記錄 `/design` 做出的畫面設計。做前端（`/frontend-design`）時，請先讀 `docs/architecture.md`，再讀這份。
> 設計稿是靜態的（不會動），只定義「長什麼樣子」。行為以 `architecture.md` 第 7 章「畫面清單」為準。

## 設計稿位置

- 設計畫布（私人連結，只有建立者能開）：https://claude.ai/artifact/FLGyGF5GsnYf7LF9D6oHPN
- 共用樣式原始碼：`docs/design/pixel.css`（設計稿實際使用的樣式，做前端時可直接沿用或改寫成元件樣式）

## 風格

日系復古像素風，像 90 年代日本 RPG／Game Boy 遊戲。手機優先，另有電腦版；淺色與夜晚（深色）兩套配色。

- 對話框像 RPG 文字框：直角缺角的像素邊框（用 `box-shadow` 疊出，沒有圓角），加硬邊陰影
- 小裝飾：像素櫻花、像素愛心、星星（★ ☆）
- 進出提示像遊戲訊息：「★ 小明 加入了冒險！」「☆ 小美 離開了冒險…」
- 最新一則訊息右下角有會跳動的「▼」（RPG 的「下一頁」游標）
- 文字清楚好讀是第一優先，不為了像素風犧牲可讀性

## 字體與大小

- 字體：`'DotGothic16', 'Noto Sans TC', sans-serif`（Google Fonts）
  - DotGothic16 是日文像素字體，少數繁體字沒有字形，會自動退回 Noto Sans TC，那些字不會是像素風。如果想要更完整的中文像素字，做前端時可以評估自行放入 Zpix 之類的像素字體（需確認授權）。
- 內文 16px、行高 1.55
- 標題「像素聊天室」：進入頁 28px、標題列 18px（電腦版 20px）
- 次要文字（時間、提示、字數）12～14px
- 觸控目標：所有按鈕最小 44px 高（小按鈕 `.sm` 為 36px，只用在標題列和「↓ 有新訊息」，如要改成純觸控介面建議放大）

## 像素元素的做法

| 元素 | 做法 |
|---|---|
| 缺角像素邊框 | 四個方向各一道 3px 的 `box-shadow`（上下左右，不含四角），變數 `--bx` |
| 硬邊陰影 | `box-shadow: 6px 6px 0 var(--shade)`；夜晚版改成粉色光暈 |
| 按鈕立體感 | 內側高光與暗部 `inset` 陰影；按下時往右下移 3px |
| 像素圖示 | 內嵌 SVG，`shape-rendering="crispEdges"`，顏色用 `currentColor` |
| 像素櫻花 | 5×5 格的 SVG（粉色花瓣、黃色花蕊）|
| 像素愛心 | 7×6 格的 SVG，用在標題 |
| 笑臉／圖片圖示 | 7×7 格的 SVG，分別用在 emoji 與圖片按鈕 |
| 背景花紋 | `radial-gradient` 小圓點，16px 間距 |

## 各畫面的版面

### 進入頁（手機）
- 垂直置中：粉色標題框（愛心＋「像素聊天室」＋一句說明）→ 表單框（標籤、輸入框、字數、錯誤訊息、按鈕）→ 底部小提示
- 背景有散落的像素櫻花、星星、愛心（`.deco`，絕對定位、不可點擊）
- 電腦上同樣置中，寬度限制約 390px（設計稿沒有另外畫電腦版進入頁）

### 聊天室（手機）
由上到下：標題列 → （斷線提示）→ （名單面板）→ 訊息區（填滿剩餘高度）→ 正在輸入列 → （emoji 面板）→ 輸入區。
- 名單展開時，訊息區被擠短，仍然可以捲動
- 輸入區內由左到右：emoji 按鈕、圖片按鈕、輸入框、送出按鈕；字數在下一列靠右
- 有圖片預覽或錯誤訊息時，插在輸入區頂部

### 聊天室（電腦）
- 標題列橫跨整個寬度
- 下方分兩欄：左邊訊息區＋正在輸入＋輸入區；右邊 260px 在線名單（單欄）

## 狀態一覽

| 狀態 | 畫面表現 |
|---|---|
| 代號錯誤／重複 | 進入頁表單內黃色錯誤條 |
| 代號為空 | 進入按鈕停用（半透明） |
| 斷線 | 標題列下方黃色提示；輸入框、emoji、圖片、送出按鈕全部停用；輸入框 placeholder 改為「連線中斷，暫時不能送出」 |
| 圖片錯誤／送太快 | 輸入區頂部黃色錯誤條（可同時出現多條） |
| 圖片預覽 | 輸入區頂部顯示縮圖、檔名、大小與「取消 ✕」 |
| emoji 面板開啟 | emoji 按鈕變成粉色（按下狀態）；面板在輸入區上方，頁籤：笑臉／動物／食物／符號 |
| 圖片放大 | 全螢幕深色遮罩，置中大圖，下方提示與「關閉 ✕」按鈕 |
| 往上翻舊訊息時有新訊息 | 訊息區右下角出現「↓ 有新訊息」 |

## 動畫

| 動畫 | 做法 |
|---|---|
| 正在輸入的點點 | 三個 6px 方塊依序往上跳 4px、亮度變化，週期 1.2 秒，段落式（`steps(1)`），有像素感 |
| 最新訊息的「▼」 | 上下各跳 3px，週期 1 秒 |
| 按鈕按下 | 往右下平移 3px |

> 建議：做前端時加上 `prefers-reduced-motion` 判斷，偏好減少動態的使用者關閉上述動畫（設計稿尚未處理）。

## 無障礙

- 所有按鈕是真正的 `<button>`，圖示按鈕有 `aria-label`
- 輸入框都有對應的 `<label>` 或 `aria-label`
- 錯誤提示 `role="alert"`，斷線提示 `role="status"`，正在輸入列 `aria-live="polite"`
- 名單展開按鈕用 `aria-expanded`；emoji 按鈕用 `aria-pressed`
- 圖片放大是 `role="dialog"` 加 `aria-modal`
- 純裝飾的 SVG 與符號用 `aria-hidden="true"`
- 焦點樣式：虛線外框 3px（`:focus-visible`），顏色使用 `--pink-d`

## 做前端時的注意事項

1. **設計稿裡的訊息、代號、人數都是示範資料**，階段一的 `MockChatService` 可以直接用它們當假資料來源。
2. **設計稿沒有做、需要前端補上的**：
   - 電腦版進入頁
   - 「接近 500 字」時字數的提示樣式
   - 圖片載入中的樣子
   - `prefers-reduced-motion`
   - 使用者系統是深色模式時，自動套用夜晚配色（`prefers-color-scheme`），以及手動切換夜晚版的方式（`architecture.md` 第 10 章寫「深色模式切換」不做，所以建議**只跟隨系統設定**）
3. **圖片的像素風縮圖只是示意**：真實圖片是使用者上傳的照片，顯示時保持原比例，保留像素風邊框即可。
4. **emoji 面板**設計稿只畫了笑臉分類的前 24 個，實際用 `architecture.md` 第 3.1 章提到的套件時，外觀要調整成與設計稿一致（邊框、頁籤）。
5. **字體可能有缺字**，上線前用實際訊息內容檢查中文顯示。
